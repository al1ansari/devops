Monolithic architecture vs Microservice Architecture => app dev
===================================================

Note : refer to the board work diagram attached in live class recordings 

==> Monolithic architecture : If we develop all functionalities/services as a single app

Limitation/Drawbacks 
--------------------
=> Everything in one place
=> Single Point of failure
=> Burden on Server
=> Maintenance will be difficult
=> Re-Deploy Entire app which increase down time 

==> Microservice architecture : Small services/api which are independently deployed
    (Developing app as multiple services/apis depends on funcationalities)

Benefits
--------
=> Loose coupled
=> High availability
=> Tech independence
=> If there is a problem in one feature/api/microservice the other services need not to be redeployed (Hence less down time)

SDLC ==> Software Development Life Cycle
========================================

==> Requirement Gathering
==> Requirement Analysis
==> Design / Planning
==> Development (coding)
==> Testing
==> Deployment/ Delivery
==> Maintenance --> support 

=========================================

1) Waterfall Model (outdated)
   -> Requirement are fixed
   -> Duration is fixed
   -> Budget fixed
   -> Client will be able to see project at the end (Client involvement will not be there)
   -> No Agility ( no flexibility)
   -> Longer delivery time

2) Agile Methodology (trending)
  
   -> Planning + Development + Testing + Deployment is a continuous process
   -> Iterative approach

   -> Project requirement is not fixed
   -> Project is not fixed
   -> Project duration is not fixed
   -> Project will be developed in multiple sprints
   -> Client involvement will be there in every sprint
